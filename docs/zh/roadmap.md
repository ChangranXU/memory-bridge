# 路线图

按层规划的开发计划。

## 计划中

### 第 4 层——实验性

* **智能体可移植性**——第二个智能体集成（mini-swe-agent 之外），以验证适配器模式并记录移植面（约 200 行智能体钩子层；后端和集成保持不变）。
* **`persistent_slot` 臂**——持久的召回槽位，跨步骤保留在对话中，解决每步注入重复的 token 浪费问题。
* **mem0 可选的每仓库作用域**——mem0 在任何模式下都没有桥接端作用域；在那里分层需要元数据过滤（cure\_memory 臂的两层作用域——仓库级 vs 通用——已经落地）。
* **`extract_max_message_chars`**（机制待定），将追踪代码从 `backend.py` 拆分为 `trace.py`，以及 CURE 提取器适配。

## 设计不变量

这些属性在所有未来工作中保持不变：

{% hint style="warning" %}
这些不变量不可商量——它们定义了 memory-bridge 是什么。
{% endhint %}

* 添加新的记忆系统必须**不需要修改 `shared-bridge`**（零命名扫描是一个测试）。
* Schema-v6 事件形状保持稳定。
* 标注保持纯可观测性——新能力永远不以失效封闭纪律换取行为风险。
